# Native virtual / owner-data report list

The fifteenth topic compares an ordinary populated SysListView32 with a separate report list created with LVS_OWNERDATA. The ordinary list stores three sample rows through LVM_INSERTITEM/LVM_SETITEMTEXT. The owner-data list advertises 1,000 items through LVM_SETITEMCOUNT and answers LVN_GETDISPINFO text requests from a bounded map of stable dummy IDs. Strings are generated only when requested; there is no external I/O or one HWND per row. The on-screen request count may repeat for the same text and is not a performance benchmark.

Windows draws the report, SysHeader32 headings, selection, scrolling and focus behavior. Owner-data describes where item data comes from; it is distinct from WM_DRAWITEM owner drawing and NM_CUSTOMDRAW color changes. The app does not dynamically toggle LVS_OWNERDATA on an existing control. See Microsoft's [list-view overview](https://learn.microsoft.com/en-us/windows/win32/controls/list-view-controls-overview) and [window styles](https://learn.microsoft.com/en-us/windows/win32/controls/list-view-window-styles).

Click any heading to sort the application's ID map; click again to reverse its direction. ID ordering is numeric, category ordering alphabetical and generated-value ordering numeric. Ties use stable IDs. The native header displays a sort arrow and the selected record follows its stable ID. First/last native Button controls select the displayed endpoints. Selection is ordinary native row selection, independent of the sensor topic's app-managed active cell. Scroll the gallery body to reach the selected-value label and buttons below the report.

The callback validates row, ID and subitem bounds, copies at most cchTextMax - 1 characters into a usable supplied buffer and terminates it. It retains no pointer to a temporary generated string. Invalid requests return empty text. UI statistics update through a posted message outside the callback. Microsoft's [LVN_GETDISPINFO reference](https://learn.microsoft.com/en-us/windows/win32/controls/lvn-getdispinfo) and [LVM_SETITEMCOUNT reference](https://learn.microsoft.com/en-us/windows/win32/controls/lvm-setitemcount) describe these APIs.

LVM_GETITEMTEXT and LVM_SORTITEMS are not supported for owner-data lists. The app sorts its own map; its audit retrieves native callback text through LVM_GETITEM. It tests all 3,000 row/subitem combinations, native callback dispatch, short/zero/null/sentinel buffers, invalid indices and IDs, model/native count agreement, both sort directions, stable selection and header glyphs, no-selection state, first/last commands, DPI/theme retention, 16 repeated visits and bounded GDI/USER/window resources. No physical keyboard or mouse input is injected.

This is a practical bounded example, not a complete virtual-data framework. Filtering, editing, asynchronous providers, LVN_ODCACHEHINT caching and LVN_ODFINDITEM type-ahead are not demonstrated. Physical focus/keyboard behavior and accessibility inspection remain manual checks. See Verification.md and the snapshot's own audit reports for tested rendering and launch behavior.
