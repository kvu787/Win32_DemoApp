# Native row selection and application-managed cell selection

The Sensors/details topic offers two working modes over the same SysListView32 report control and SysHeader32 header. Both mode selectors are Button windows with BS_AUTORADIOBUTTON. The selected-value label is a Static window.

Row mode uses the native LVS_SINGLESEL and LVS_EX_FULLROWSELECT behavior. LVS_SHOWSELALWAYS lets Windows display an inactive selected row when a mode button has focus. Cell mode removes full-row selection and keeps one active sensor ID/column in application state. Native rows are not marked LVIS_SELECTED in Cell mode. The app requests subitem custom-draw stages and applies system highlight/text colors only to the active cell, retaining native text, icons, headers and report layout.

Click any of Sensor/Current/Minimum/Maximum or use Left/Right/Up/Down in Cell mode. Arrows stop at the first/last row or column. Header, below-row and right-margin hits do not clear the active cell. The label identifies the sensor, column and value; group cells with no numeric value are labelled empty. Enter or a double-click on the CPU group expands/collapses its fixed dummy children. A selected child that disappears falls back to the visible group with its column retained. Stable IDs preserve GPU selection when its row index changes. Switching modes and DPI/theme refresh preserve valid selection state.

The mouse handler uses [LVM_SUBITEMHITTEST](https://learn.microsoft.com/en-us/windows/win32/controls/lvm-subitemhittest), then checks native header/item bounds. [NM_CUSTOMDRAW](https://learn.microsoft.com/en-us/windows/win32/controls/nm-customdraw-list-view) supplies item/subitem paint stages. The app uses CDRF_NOTIFYSUBITEMDRAW for cell colors and CDRF_SKIPPOSTPAINT to suppress the native row focus rectangle in Cell mode. These APIs extend the native control; they do not create a stock cell-selection control.

The floating sensor window keeps native row selection. This example does not add editing, multiselection, formulas, a spreadsheet framework or a custom cell-level UI Automation/MSAA provider. Native list-row accessibility and the value label remain; custom cell semantics need a provider in a production application.

Hidden Release/Debug audits verify native classes/styles per mode, all four columns and blank hit regions, mouse-message handlers, arrow boundaries, value labels, subitem color decisions, hierarchy fallback, 32 collapse/expand cycles with unchanged dummy data, DPI/theme retention and stable GDI/USER resources. They use messages sent to this app's HWNDs, without system input injection or focus manipulation. Actual mouse/keyboard focus traversal and accessibility inspection remain unverified. Visual Row/Cell captures and actual root-launcher checks require a coordinated unlocked NE18NZ2 slot; hidden checks alone do not establish visible rendering.
