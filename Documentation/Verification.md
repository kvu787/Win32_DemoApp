# Verification

The project was built on Windows 11 x64 using the existing MSVC 19.51.36260 toolchain and Windows SDK 10.0.26100.0, with no installation, network dependency, push or system setting change. Both Release and Debug builds passed hidden native-control audits. The direct MSVC Build.ps1 path is verified; an initial CMake/Ninja compiler probe stalled and was stopped, so CMake is provided for IDE use but is not claimed verified here.

The last verified ready snapshot contains authoritative IndependentLaunch.txt and GuiAudit.txt reports in Verification. The executable was launched from a different working directory to verify that resources are embedded and no source-tree or runtime-package dependency is needed. BuildInfo.json records the source commit and executable SHA-256. All snapshot files are read-only and ready folders are never overwritten by the scripts.

The subsequent review corrections were initially built and audited while the machine was locked. Historical candidates contain their own hidden reports and preserve the previous ready pointer. The current owner-data checkpoint extends coverage to 15 topics; Release and Debug hidden tests create 2,098 controls. An unlocked, cleared NE18NZ2 run passed the no-activation GUI audit and supplied fresh app-only captures. Ready publication requires a fresh copied-executable GUI audit plus both actual root launcher checks; BuildInfo.json and that snapshot's reports establish whether those checks passed. Historical captures are never reused for a candidate. See ReviewCorrections.md for the fixes and remaining manual acceptance work.

## Checks performed

- All 15 topics and expected native classes create successfully. The audit recreates all topics across eight additional cycles (120 topic recreations), plus targeted fixtures and 16 owner-data topic visits. Each report records its authoritative control count; hidden and visible counts differ because hidden-only owned-window fixtures are omitted in visible mode.
- The embedded manifest establishes Per-Monitor V2 awareness; Comctl32 DllGetVersion confirms v6. Theme activation and application theming are reported separately. Windows 11 themed buttons, command links, editors, trees, reports, tabs, rebar and calendars were visually inspected in app-only captures.
- Three-state/disabled/checked button states, command-link notes, slider-to-progress notifications, progress error state, dependent enabled state and list-view report/icon switching are checked through native messages.
- Dialog resources 101/102/103 are present; a native property page can be created and released. The Shell Common Item Dialog COM object can be created without showing it.
- Tab-order lookup resolves without changing focus. Actual focus traversal was not injected.
- Scroll position and 96/144/192 DPI font/layout refresh are tested. Shared icon sizes are also verified against synthetic DPI. Current regressions check that presentation refresh retains HWNDs, edited buffers, selection, logical scrolling and control values. Hidden WM_DPICHANGED handler tests verify rectangle ordering, tracking dimensions and retained splitter/deep-scroll/input state in both 96-to-192 and 192-to-96 directions. Real monitor transitions remain untested.
- Isolated temporary launcher fixtures execute the real root PowerShell script with Start-Process mocked. Missing/malformed pointer overrides, ordinary pointer selection and rejection guards pass without native process creation. These tests do not verify actual launcher visibility.
- Sensor Row/Cell regressions verify native classes/styles, all four column hits and blank regions, subclass mouse/key handlers without input injection, value/custom-draw decisions, stable sensor IDs, disappearing-child fallback, 32 collapse/expand cycles, data invariance, DPI/theme state retention and GDI/USER stability. A regression reproduced Row Enter being swallowed by IsDialogMessage; the fix reserves Return in both modes and passes actual IsDialogMessage/DispatchMessage routing. Captures show the inactive native row and one blue/white app-managed cell. Actual focused keyboard interaction remains unverified; see SensorSelection.md.
- The owner-data comparison verifies genuine LVS_OWNERDATA/report/header styles, ordinary stored rows, a 1,000-ID model/native count, native LVM_GETITEM callback dispatch, all 3,000 row/subitem requests, buffer guards, invalid indices/IDs, no HWND per row, both sort directions and stable selection/header glyphs, first/last commands, no-selection state, DPI/theme retention and 16 repeated visits with bounded resources. Fresh captures show native drawing and scrolling; OwnerData.md documents unsupported features.
- Body-font validity, shared image-list survival, tooltip registration cleanup and stable GDI/USER object counts are checked after repeated navigation. Visual inspection found font/image ownership and rebar alignment issues; those were fixed before publication.
- Visible test runs validate the exact NE18NZ2 friendly display identity and the entire test-window rectangle before showing/capturing. They use WS_EX_NOACTIVATE and SW_SHOWNOACTIVATE, inject no mouse/keyboard input and leave the foreground HWND unchanged. Captures use PrintWindow on this application's own HWND, not a desktop screenshot. Test windows close on completion.

## Explicitly unverified

Interactive modal dialog cancellation, Common Item Dialog acceptance, real property-sheet Apply/Cancel flow, actual keyboard focus/mnemonic traversal, owned floating windows' user interaction, real monitor DPI transitions, focused Row/Cell rendering, accessibility inspection tools, high contrast, alternate locales/themes and every style/message permutation require manual verification. Opening modal dialogs could activate windows, so the assistant intentionally did not automate those flows on the user's desktop. Their cancellation handlers and side-effect boundaries were reviewed in code. For actual corrected root launcher visibility, consult PowerShellLauncher.txt/CmdLauncher.txt in a ready snapshot; mocked launcher checks alone do not establish visibility.

File dialogs return paths only; no application file-open/write action follows them. FOS_NOCHANGEDIR and FOS_DONTADDTORECENT are set. Color/font apply only to a temporary sample; Find/Replace modifies a temporary buffer; the property sheet has no system-configuration calls. Print/page setup is excluded entirely.

Source screenshot pixels could not be materialized in this execution environment. ScreenshotGuide.md preserves the parent's verified conceptual inventory and source identifiers; local visual checks cover the generated gallery, not exact replicas of the source applications.
